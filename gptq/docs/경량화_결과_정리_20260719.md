# 한국어 VLM 4bit 경량화 — Jetson 8GB 탑재까지

가짜연구소(Pseudo Lab) 프로젝트 · 작성: 정수인 · 2026-07-19

## 요약

**Jetson Orin Nano 8GB에서 실제로 돌아가는 한국어 비전언어모델(VLM)을 만들었습니다.**
한국어 특화 Kanana-1.5-v-3b를 NF4 4bit로 경량화하여 품질 손실 없이(K-DTCBench 78.75% → 81.25%) 모델 크기를 7.34GB → 2.66GB(−64%)로 줄였고, 7월 19일 Jetson 실기기 탑재까지 검증을 완료했습니다 (peak VRAM 2.86GB, 한국어 VQA 응답 정상).

## 1. 프로젝트 목표

Jetson Orin Nano(8GB)급 엣지 장비에서 구동 가능한 한국어 VLM 만들기.
원본 모델은 VRAM을 초과하므로 4bit 양자화 등 경량화가 필수였다.

## 2. 1차 시도: Llama-3.2-11B-Vision GPTQ 4bit

- Llama-3.2-11B-Vision-Instruct를 GPTQ로 4bit 양자화: **21GB → 11GB**
- Windows 환경에서 gptqmodel의 함정(pyarrow DLL 충돌, 멀티모달 모듈 트리 등) 다수를 해결하며 양자화 파이프라인 완성

### 핵심 발견: 캘리브레이션 데이터의 언어가 품질을 좌우한다

GPTQ 양자화 시 영어 캘리브레이션 데이터만 쓰면 **한국어 성능만 선택적으로 열화**된다.

| 캘리브레이션 | 한국어 PPL 열화율 |
|---|---|
| 영어 only | +19.6% |
| **한국어 혼합** | **+6.6%** |

한국어를 섞은 캘리브레이션으로 재양자화하여 열화를 1/3로 줄였다. 이 프로젝트의 독자적 발견.

## 3. 한계 확인 → 전략 전환

- 11B는 한국어 벤치마크 K-DTCBench(4지선다, 240문항)에서 **29~35%** — 랜덤(25%)과 사실상 동급. 양자화 품질을 비교할 기반 자체가 없었다.
- Jetson 8GB 탑재도 실패: 3bit 양자화(−0.9GB, PPL +47%), 레이어 프루닝(2층 한계), 비전 경로 NF4(8.15GB)까지 시도했지만 전부 미달. 병목은 fp16으로 남는 비전 경로(~4.5GB).
- **결론: "큰 영어 모델을 압축"이 아니라 "한국어 특화 소형 모델을 압축"으로 전환.**

## 4. 2차 시도: Kanana-1.5-v-3b + NF4 (최종)

카카오의 한국어 특화 VLM Kanana-1.5-v-3b-instruct에 NF4(NormalFloat4, bitsandbytes) 적용.
NF4는 캘리브레이션이 필요 없어(2절의 언어 편향 문제 원천 차단) 로드 시 즉석 변환되고, 텍스트·비전 구분 없이 모델 전체를 4bit로 적재한다.

**데스크톱(RTX 3080 Ti) 측정 결과:**

| 구성 | K-DTCBench (240문항) | 한국어 PPL | 영어 PPL | 가중치 | Peak VRAM |
|---|---|---|---|---|---|
| fp16 (원본) | 78.75% | 6.83 | 14.09 | 7.34GB | 8.18GB |
| **NF4 4bit** | **81.25%** (+2.5pp) | 7.14 (+4.5%) | 15.01 (+6.5%) | **2.66GB** | **3.59GB** |

- 품질 손실 사실상 0 (K-DTCBench는 오히려 상승, 노이즈 범위)
- K-DTCBench 세부(NF4): 문서 91.3% / 표 86.3% / 차트 66.3%

## 5. Jetson Orin Nano 8GB 실기 탑재 (2026-07-19 완료)

NF4 가중치를 오프라인 완결 체크포인트로 저장해 Jetson에 이관, Tailscale 원격으로 탑재 검증 완료.

| 항목 | Jetson 실측 |
|---|---|
| 모델 로드 | 45.2초 |
| 가중치 | 2.66GB |
| **Peak VRAM** | **2.86GB** (8GB 중) |
| 생성 속도 | 2.24 tok/s (이미지 인코딩 포함) |
| 한국어 VQA | 정상 응답 확인 ("이미지에는 빨간색 원과 파란색 사각형이 보입니다…") |

k3s/도커 등 운영 인프라와 공존하면서도 여유 있게 구동. Jetson 특유의 이슈(통합메모리 OOM, aarch64 전용 휠, NumPy 호환)를 해결한 재현 절차도 확보했다.
