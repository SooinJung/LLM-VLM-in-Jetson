# Llama-3.2-11B-Vision GPTQ 경량화 정리 (Phase 1)

가짜연구소(Pseudo Lab) 프로젝트 · 작성: 정수인 · 2026-07-19

## 개요

프로젝트 1단계로 **Llama-3.2-11B-Vision-Instruct**(영어 중심 멀티모달 11B)를 GPTQ 4bit로 경량화하고, 한국어 성능·Jetson 8GB 탑재 가능성을 검증했다. 결과적으로 "11B로는 안 된다"는 결론과 함께 **캘리브레이션 언어의 중요성**이라는 핵심 발견을 남겼고, 이것이 Kanana-3B 전환(Phase 2)의 직접적 근거가 됐다.

## 1. GPTQ 4bit 양자화 완성

- 텍스트 레이어 4bit 양자화: **21GB → 11GB** (비전 인코더·크로스어텐션은 mllama 구조 특성상 fp16 유지)
- 양자화 무결성 검증 PASS
- Windows + 멀티모달 조합에서 gptqmodel의 함정 6종(pyarrow DLL 충돌로 인한 segfault, module_tree 누락, meta device 오류, triton 부재 등)을 전부 해결 — `src/mllama_compat.py` 선(先) import 한 방으로 정리

## 2. 핵심 발견: 캘리브레이션 데이터의 언어가 품질을 좌우한다

GPTQ는 캘리브레이션 데이터로 양자화 오차를 보정하는데, 관례대로 **영어 데이터만 쓰면 한국어 성능만 선택적으로 열화**된다는 것을 확인했다.

**Perplexity (낮을수록 좋음, seq_len 1024):**

| 구성 | 영어 PPL | 한국어 PPL | 한국어 열화율 |
|---|---|---|---|
| fp16 (원본) | 8.21 | 8.57 | — |
| GPTQ 4bit, 영어 캘리브 | 8.81 | 10.25 | **+19.6%** |
| **GPTQ 4bit, 한국어 혼합 캘리브** | 8.74 | 9.14 | **+6.6%** |

- 영어 캘리브에서 영어 열화는 +7.3%에 그치는데 한국어는 +19.6% — 명백한 언어 편향
- 한국어를 섞어 재양자화하자 한국어 열화가 **1/3로 감소** (영어 성능 손해 없음)
- 실무 시사점: *다국어 모델을 양자화할 때는 캘리브레이션 데이터에 대상 언어를 반드시 포함해야 한다*

## 3. 두 번째 발견: 11B는 애초에 한국어가 안 됐다

한국어 문서 VQA 벤치마크 **K-DTCBench**(4지선다 240문항, 랜덤 = 25%)로 측정한 결과:

| 구성 | 정확도 |
|---|---|
| fp16 (원본) | 29.2% |
| GPTQ 영어 캘리브 | 35.4% |
| GPTQ 한국어 캘리브 | 30.4% |

세 구성 모두 **랜덤 수준의 노이즈** — 원본부터 한국어 능력이 없어서, 양자화 품질을 비교할 기반 자체가 없었다. "영어 대형 모델을 압축해서 한국어 서비스에 쓴다"는 전제가 성립하지 않음을 확인했다.

## 4. Jetson 8GB 탑재 시도 — 전부 미달

11GB를 8GB 아래로 내리기 위한 추가 압축 시도:

| 시도 | 크기 | 결과 |
|---|---|---|
| GPTQ 3bit (한국어 캘리브) | −0.9GB | PPL +47% 급락 — 품질 붕괴로 기각 |
| 레이어 프루닝 | — | 민감도 분석 결과 2층이 한계 — 효과 미미 |
| NF4 전체 4bit (비전 포함) | **8.15GB** (−3GB) | 품질 준수(KO PPL +7.7%)했지만 여전히 8GB 초과 |

근본 병목은 **fp16으로 남는 비전 경로(~4.5GB)**. 텍스트를 아무리 압축해도 비전 인코더+크로스어텐션이 fp16인 한 8GB 진입이 불가능했다. (NF4로 비전까지 4bit화한 8.15GB가 최선이었으나, 추론 시 활성값까지 고려하면 실가용 미달)

## 5. 결론 — Phase 2로 이어진 교훈

1. **캘리브레이션 언어 발견** → Kanana에서 캘리브레이션이 아예 불필요한 NF4 채택의 근거
2. **11B의 한국어 부재** → "큰 영어 모델 압축"에서 "한국어 특화 소형 모델(Kanana-3B) 압축"으로 전략 전환
3. **비전 경로 병목** → 텍스트/비전 구분 없이 모델 전체를 4bit로 적재하는 NF4 방식 채택

이 전환의 결과가 Phase 2: Kanana-1.5-v-3b NF4 — K-DTCBench 81.25%(품질 손실 0), 2.66GB, Jetson Orin Nano 실기 구동 검증(7/19)이다. 상세는 `경량화_결과_정리_20260719.md` 참고.
